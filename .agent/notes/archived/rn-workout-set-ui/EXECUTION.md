依赖 [设计 v1](DESIGN.md)，源码基线 `42411be33`。状态为已实施并通过 Android 模拟器验收（2026-11-20）；结果与证据见 [验收记录](ACCEPTANCE.md)。

## 1. 开始前

1. 在 `D:\dev\open-gym` 用 PowerShell 7 执行 `git status --short` 和 `git rev-parse --short HEAD`。核对新提交是否修改了训练、休息或同步入口。发现既有改动先保留并定位冲突，记录实际实施基线。本轮实际基线为 `42411be33` 之上的工作区改动；工作区同时存在独立的动作检索改动，训练相关文件由本轮维护。
2. 阅读 [项目地图](../../AGENTS.md)、[openGym 开发技能](../../.agents/skills/opengym-development/SKILL.md)、[训练设计系统](../../docs/RN_UI_DESIGN_SYSTEM.md)、[页面迁移](../../docs/RN_UI_SCREEN_MIGRATION.md)和 [视觉验收](../../docs/RN_UI_VISUAL_TESTING.md)。核对训练的 [RN 迁移清单](../../docs/RN_MIGRATION_STATUS.md) 与 [递减组既有用例](../rn-p2-training-library/02_DROP_SETS.md)。
3. 与需求方确认设计 §4 中已完成后的结构编辑、取消完成和休息规则。T1–T2、T3 的未完成分段路径可先推进。暂定规则未确认前，将完成后的结构编辑保持关闭，把 V09 的后半部和最终交付列为待确认。变更决定时先同步修改设计、计划和用例。
4. 为专项与集成使用单独 AVD、串口、产物目录和测试数据。下文示例集成设备为 `emulator-5556`，实际执行用 `adb devices -l` 核对。fixture 会改写该设备的应用数据，仅应用于专用 Debug 模拟器。同步用独立 API 和测试账户。

## 3. 工具、构建和视觉检查

在仓库根目录按 [Android 构建](../RN_ANDROID_EXECUTION.md#windows-构建) 和 [工具链说明](../../.agents/skills/opengym-development/references/rn-android.md) 核对实际安装路径。各任务合入后执行以下检查。预期命令退出码为 0，已有 lint 警告单独记录。

```powershell
Set-Location -LiteralPath 'D:\dev\open-gym'
npm.cmd --prefix .\mobile-rn run typecheck
npm.cmd --prefix .\mobile-rn run design:check
npm.cmd --prefix .\mobile-rn run lint
```

依赖缺失时在 `mobile-rn` 执行 `npm.cmd ci`。安装匹配当前代码的 Debug 客户端并按工具链说明连接 Metro。以下为集成 Debug 模拟器的指令。它要求设备已启动、客户端可被 `run-as` 访问。视觉脚本使用 `fixture-upper`，覆盖基础训练页。递减组的收起、展开、各菜单、底部表单和键盘由 V01、V04–V07 操作并补专项截图。

```powershell
Set-Location -LiteralPath 'D:\dev\open-gym\mobile-rn'
$adb = Join-Path $env:LOCALAPPDATA 'RnToolchain\android-sdk\platform-tools\adb.exe'
$serial = 'emulator-5556'
& $adb devices -l
& $adb -s $serial reverse tcp:8081 tcp:8081
.\scripts\ui-capture.ps1 -Serial $serial -Fixture -OutDir .\dist\workout-set-ui\integration-ui
```

常规预期是脚本生成页面截图和 contact sheet。脚本失败时记录失败页面及设备日志，先确认安装包与 Metro、fixture 及控件标签。遇到现有脚本没有覆盖的新交互，补手工记录，不用单张静态截图判断计时。采集可复核的单个状态时，使用 `adb shell screencap` 和 `adb pull`，文件存相应专用目录。

候选包按 [Android 构建指令](../RN_ANDROID_EXECUTION.md#windows-构建) 运行 `prebuild` 与 `gradlew.bat :app:assembleRelease`，输出路径为 `mobile-rn/android/app/build/outputs/apk/release/app-release.apk`。再用 SDK Build Tools 的 `apksigner verify`、`aapt dump badging` 和 PowerShell `Get-FileHash -Algorithm SHA256` 核对候选。构建失败时保留日志，先排查现有工具链或短路径问题，随后用相同源码重新构建，历史 APK 不充当本版验收证据。

## 4. 验收准备和执行分工

**验收设备仅限 Android 模拟器。** V01–V11、专项验收和可见集成验收都在模拟器执行，真机验收无需安排，也不计入本轮交付条件。

- **测试数据 A**。使用 fixture 的力量训练或手动创建计划：动作 A 至少 3 个正式组，有自动热身，首个正式组可设为 `60 kg × 7`。后面还有未完成组，动作休息设为 60 秒，有第二个动作，设置为 RPE 评分。准备一套关闭评分、RIR 及有氧或计时组的补测数据。
- **测试数据 B**。组合同一轮两个各有两组的力量动作，第一个动作的第 1 组设为递减组。用基线客户端在隔离设备建立旧草稿，先设为递减组且不勾选，关闭 App，作为旧未完成样本。另起一份草稿，勾选整组后收起训练，作为旧已完成样本。保持相同包名与签名覆盖安装候选客户端来验证恢复。也可复制两份基于基线 `DraftSet` 的 fixture，显式省略新增完成字段。另准备一套旧休息暂停计划。每次恢复前先记录初始状态。
- **专项验收**。按技能安排独立无头模拟器验证用例，可用同一确认版本的源码或包，各自保存截图、日志和实际结果。避免复用有个人数据的设备或工作区状态。
- **可见集成**。主 Agent 在可见模拟器从计划开始训练，完成热身、普通组和递减组，经历一次草稿恢复，完成后查看历史并同步。计时用例必须从新进程正常开训，深链不附 `e2e=1`。视觉 fixture 与实时时钟用例分别保存证据。

## 5. 验收用例

| ID | 操作与前置 | 预期与证据 | 任务 |
|---|---|---|---|
| V01 | 用 A 打开卡片、列表和紧凑布局。以 360 dp 和 320 dp 可用窗口检查，再测试放大系统字体。点重量、次数，输入小数和整数。清空后失焦 | 主行列对齐。控件互不遮挡，点数字弹对应键盘，不触发完成或菜单。无效输入回退。记录窗口、字体设置、截图与控件树。补测有氧和计时字段 | T1 |
| V02 | 对正式组填写 RPE 8，改分、清除，切到 RIR。查看热身、历史草稿里的已评分行及关闭评分时的卡片。完成一组未评分的递减组，随后从主行补填 | 评分在同一行，空时显示 `—`。已存尺度不被切换设置改写。热身评分位不可点。断开键盘后评分面板可正常打开。递减组只在主行提供一个可选评分，逐段勾选不弹评分，也不等待评分再开始休息 | T1、T3 |
| V03 | 未记组前打开动作右上菜单并搜索替换。记普通组或递减组主段后再次打开。分别点动作菜单和组尾菜单 | 搜索只在动作菜单。未记任何段时可替换，已记组或段后锁定。组尾没有替换动作 | T1、T3 |
| V04 | 普通组改热身再改回。复制普通组、热身组和有评分及已勾段的递减组。尝试删除未完成组和查看已完成组菜单。用有运行休息条的草稿移动、插删其他行 | 标签和排序正确。保留数值及原组完成状态，热身清除评分。新行带参数但没有勾选、评分和完成时间。删除限制有效。休息引用仍指向原组，倒计时不重置 | T2、T3 |
| V05 | 普通组点「改为递减组」。确认面板初始一段。输入非法值点保存，修正后先取消，重新打开再保存。随后打开「编辑分段」改一段数值并保存 | 未保存前原组不变。非法输入留在面板并标出错误。取消无副作用。保存后变递减组并自动展开，`0/2`，无新休息。编辑后摘要同步更新 | T2 |
| V06 | 让递减组 `1/3`，在展开区点添加。查看预填并手改。再测编辑页删除某段、删光降重段及组尾「改为普通组」。对已有勾选降重段分别取消和确认还原 | 追加后 `1/4` 且原勾选保留。编辑以分段标识保持进度。若删除导致全部剩余段已勾，拒绝这种隐式完成。取消确认保留记录，确认后只留主段，不触发新休息 | T2、T3 |
| V07 | 用 A 完整勾选递减组。中途尝试跳段，切专注再回卡片并继续。专项中重复投递同一条最后一段完成命令，观察休息归属和起点 | 展开后，直接点分段勾选框。主段及中间段勾选只更新进度。切换布局读到同一状态。最后一段只产生一次完成和一次符合现有规则的休息，倒计时不被重复命令重置。记录前后时间点及屏幕状态 | T3 |
| V08 | 在 B 中勾完递减组。切到下一成员，勾完整轮，再测补录、休息关闭以及整场最后一组 | 中段不推进轮次。递减组整组完成进入下一成员。最后成员完成后才按轮次规则休息。补录、休息关闭和最后一组沿用组级原规则，自动结束提示最多出现一次 | T3 |
| V09 | 勾一段后收起训练并从底栏重开，再强制停止并重开。分别读回缺少分段字段的旧未完成、已完成草稿。确认已完成后的规则后，测试取消本组最后一段，以及另一个组正在休息时的撤销 | 实际进度、重量和次数可恢复。旧未完成显示 `0/N`，旧已完成显示 `✓`。撤销最后一段回到进行中并只清本组休息。完成组的结构编辑开关与确认版本一致 | T3 |
| V10 | 在可见模拟器从计划开训，记普通组，再做 `60×7 → 50×8 → 40×9`。另留一个部分勾完的递减组，尝试结束并先取消，继续后完成并保存。另起一份短训练，实际确认部分完成保存。同步到独立实例，读回 Web 或 API | 结束确认说明部分勾选组的保存语义，取消后草稿完好。确认部分完成保存时，未完成组不计作已完成。完成结果中该递减组只有一条正式组及两段，训练量贡献应为 `1180 kg`。线上载荷以 `type/drops` 表达，无草稿勾选字段，没有重复组 | T3、T4 |
| V11 | 检查普通组和热身组菜单，再启动既有休息暂停计划、恢复旧草稿并打开既有记录 | 无新增或转换到休息暂停入口。已有分段可按兼容路径查看和记录。整组勾选与历史投影仍有效，原计划参数和历史数据未被重写 | T2、T4 |

设计 §5 的提交失败由 T3 专项补测。可在开发设备对本次 `onChange` 注入一次失败并随后恢复正常，确认最终段进度、整组完成、休息和滚动位置第一次都保持原样，重试后一次性落盘。恢复后重跑 V07，确保未把调试入口留入候选版本。

V10 可复用 [Android 回归脚本中的 API 会话与配对流程](../../mobile-rn/scripts/android-regression.ps1#L371)。用测试账户在 Web 查看训练详情，或以同一账户的 Web 会话读取 `GET /api/data` 的 `state.workouts`。按本场记录标识定位动作与组，保存脱敏后的组级 JSON。单组训练量计算以记录的重量为准。核对整场总量时，另计普通组与热身设置。
