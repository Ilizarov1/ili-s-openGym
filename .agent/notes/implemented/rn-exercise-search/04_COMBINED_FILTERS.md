## 执行步骤

1. 从目录现有 `tg` 值生成目标肌群选项，使用稳定字段值作为选项 ID，复用已有可用的中文肌群文案。将目标肌群和单侧状态并入现有筛选条件。保留部位、器械和仅收藏的行为。
2. 让 Web 原有 `isOneLimb` 判定和 RN 筛选使用同一份基于动作对象的规则。Web 保留通过目录 ID 调用的入口。RN 使用原始英文名判断内置动作，不以历史组或计划项的 `side` 推断。自建动作如有 `tg` 可按目标肌群匹配；单侧标记未知的动作只在未开启该筛选时参与。
3. 在现有 `Sheet` 增加「目标肌群」和「仅单侧」。应用后显示已选状态并增加筛选计数，沿用逐项清除和清除全部操作。搜索和详情返回后仍保留当前筛选。切换工作区时沿用 RN 现有的筛选重置时机。
4. 把所有启用的筛选条件应用为交集。筛选后形成同一候选池，供正常搜索和后续 Fuse.js 读取。无候选时显示零结果并保留筛选状态。补齐代表性的筛选状态截图；如果引入新视觉模式，按设计系统约定先补画廊。

## 测试验收标准

```powershell
npm.cmd --prefix .\frontend test -- src/lib/catalogue-defaults.existing.test.js src/lib/exercises.test.js
npm.cmd --prefix .\mobile-rn run check
```

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| 04-A | 从空查询选择「背阔肌 + 绳索 + 仅单侧」 | 包含 `1204`。检查结果 ID 对应 `tg=lats`、`eq=cable` 且单侧判定为真。普通双臂、弹力带单臂和其他目标肌群样本均被排除 |
| 04-B | 再输入「高位下拉」，逐项清除一个条件，最后清除全部 | 每次都按当前条件交集计算，结果数与芯片和面板状态一致，全部清除后恢复无筛选查询 |
| 04-C | 用冲突条件得到零结果，再清除其中一项 | 零结果时条件仍可见、可清除；解除冲突后立即出现匹配，分页从第一页开始 |
| 04-D | 检查缺 `tg` 自建动作和带 `tg` 的旧资料，开关「仅单侧」 | 缺 `tg` 时可正常按名称查；带 `tg` 的旧自建动作可按目标肌群命中；未知单侧不通过「仅单侧」 |
| 04-E | 检查筛选面板、已选状态和零结果，打开详情后返回 | 状态与查询一致，视觉遵守现有 `Chip`、`Sheet`、主题和无障碍约定；原 Web 分侧默认判断回归通过 |

完成条件为 04-A 至 04-E 通过，搜索适配层能向第 05 项提供当前筛选池。证据包括查询、筛选组合、结果 ID 和截图。
