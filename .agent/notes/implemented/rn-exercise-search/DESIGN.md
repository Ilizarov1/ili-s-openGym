# RN 常规动作检索设计

状态为已实施（代码与自动化验收通过，设备验收待补）。源码基线为 `42411be33` 及本次工作区。执行结果见 [验收记录](ACCEPTANCE.md)，入口基线见 [BASELINE](BASELINE.md)。

## 目标与范围

在 RN 现有动作库里提升普通文字搜索，覆盖动作库 Tab、计划添加、训练添加和训练替换。第一阶段先让 RN 接入 Web 已有的检索规则并验收，然后依次接入已保存的用户别名、增加组合筛选，最后用 Fuse.js 提供「你可能在找」。

本期处理动作查询和结果展示。默认别名词表、别名编辑、自建动作表单补字段、按频次重排、替代动作推荐另行讨论。自然语言条件解析、拍照和相册识别留到大模型多模态检索阶段。

Web 现有页面继续按自己的调用顺序应用筛选和个性化分组。RN 在自己的筛选范围内使用共享匹配和排序，空查询保持已有浏览顺序和收藏分组，有查询时按共享相关度排序。等分次序保持稳定。两端的对齐验收以**候选集合、语言、别名输入一致时的匹配与相对排名**为准。RN 无须全局初始化 Web 语言或账号别名状态。缓存如被复用，按候选对象及搜索上下文隔离，并在译名、别名或账号变化后失效。

### 用户别名与兼容

内置动作读取当前 `Profile.exAliases[动作 ID]`，自建动作读取自身 `aliases`，沿用 Web `exerciseAliases` 的覆盖与规范化语义。两类字段均视为可选。资料缺失或字段无有效值时按无别名处理。无论本地还是配对工作区，都从当前资料中读取，不需要搜索接口或数据迁移。`EXALIAS` 是目录 ID 变体映射，文本别名沿用独立的 `exAliases` 和 `aliases`。

### 筛选与列表

部位 `bp`、器械 `eq`、目标肌群 `tg` 和「仅收藏」沿用已有值及收藏状态。「仅单侧」使用 Web `isOneLimb` 的现有判定，对内置动作读取原始英文名；自建或未识别的动作只在未开启该条件时参与。目标肌群按目录目标 `tg` 精确匹配，次要肌群可被 Web 搜索规则匹配，但不进入目标肌群筛选。已保存且有 `tg` 的自建动作可参与该分面。参考 [目录样例 1204](../../catalogue/exercises/1204.json)。

现有筛选 `Sheet` 增加「目标肌群」和「仅单侧」，沿用设计系统组件、已选标记、筛选计数及清除路径。筛选先形成当前候选池，再执行正常查询，最后分页。筛选组合无结果时保留所选条件，便于逐项清除。按现有 `EXDB` 的来源生成目标肌群选项，复用可用的中文肌群词表，选项和值都不通过展示名称反推。

### Fuse.js 兜底

正常结果指 Web 规则跑完后的完整结果，包含它已有的容错。只在该集合为空、存在可筛候选且查询有至少四个汉字时尝试 Fuse.js。候选区复用现有动作行和选择回调，排在零结果反馈旁，独立于正常结果计数和分页。以支持名称内部匹配的 `ignoreLocation` 配置为调试起点，阈值用当前目录的正反例校准。先确认例词经正常检索确实为零，再用它验收兜底。索引按有效候选数据复用，查询输入变化不重建索引。[Fuse.js 匹配选项](https://www.fusejs.io/fuzzy-search.html)
