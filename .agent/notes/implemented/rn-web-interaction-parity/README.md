## 01 开始训练

### 当前差异与代码位置

- **Web** 底部「开始」在至少一个有效计划含动作时合并开训，其余情况进入开始选择页。首页普通「今日训练」有有效计划就启动整张清单，无有效计划时打开当日覆盖选择。首页的轮换队列行按点中的单套开训。补录从历史页进入。[底部入口](../../frontend/src/components/TabBar.jsx#L47) · [首页入口](../../frontend/src/views/Home.jsx#L120) · [开始选择页](../../frontend/src/views/Workout.jsx#L81) · [补录入口](../../frontend/src/views/History.jsx#L50)
- **RN** 只有一套推荐时直接开始，多套或没有推荐时打开底部弹层。弹层每次选一套，另有自由训练和补录。首页也是按单套计划开始，训练草稿以单个 `routineId` 构建。[开训分流](../../mobile-rn/App.tsx#L250) · [选择弹层](../../mobile-rn/src/screens/StartSheet.tsx#L29) · [首页推荐](../../mobile-rn/src/screens/HomeScreen.tsx#L246) · [草稿构建](../../mobile-rn/src/training.ts#L400)

### 修改目标与实施

1. 继续用 `recommendedRoutines` 解析当日覆盖、周排程、轮换队列和待同步历史。已有草稿时按 03 恢复。首页普通今日入口和底栏分别采用上面各自的分流，轮换卡仍按选中的计划开始。底栏打开独立选择页时，展示已有的今日计划、其他计划和自由训练。补录保留在统计里的训练记录入口。[有效计划规则](../../frontend/src/lib/history.js#L507) · [RN 推荐解析](../../mobile-rn/src/profileChanges.ts#L394) · [RN 补录入口](../../mobile-rn/src/screens/StatsScreen.tsx#L293)
2. 开训接收有序计划 ID。去除失效和重复的计划 ID，保留第一次出现的顺序。一旦开训，按清单拼接动作，空计划仍参与名称和 `routineIds`，仅贡献零个动作。同一个动作 ID 在不同计划各保留一个训练位置，记组和定位以训练位置区分。名称使用 `deriveSessionName` 的规则，单套与自由训练沿用对应名称。[合并及命名规则](../../frontend/src/lib/session-merge.js#L22) · [Web 创建训练](../../frontend/src/sheets.jsx#L3457)
3. 用 RN 现有组构建流程逐套初始化，再生成一个训练 ID 和草稿。草稿、历史和离线队列都保留有序 `routineIds`，历史兼容字段 `routineId` 取首项，动作条目保存 `rid` 和各自的 `noProg`。旧单计划草稿从 `routineId` 还原来源，自由训练使用空列表。合并场次中替换动作保留原位置来源，插入动作沿用当前训练单元的来源。[RN 初始化](../../mobile-rn/src/training.ts#L400) · [RN 动作替换](../../mobile-rn/src/training.ts#L473) · [动作来源规则](../dev/COMBINE_ROUTINES.md#8-data-model-invariants)
4. 按 `rid` 读取同计划的上次训练，找不到可用正式组时回退到全局历史，`lastFrom: 'any'` 时直接查全局。多计划历史详情按条目 `rid` 分区，轮换按场次 `routineIds` 记账。读旧训练时按 `entryRoutineId` 规则兼容原字段。[来源及历史匹配](../../frontend/src/lib/history.js#L355) · [Web 历史分区](../../frontend/src/sheets.jsx#L3254) · [轮换记账](../../frontend/src/lib/rotation.js#L299)

### 验收条件

- [ ] **01.1** 同一天依次安排「主练」「辅助」。分别从首页今日训练和底部开始入口验证，两端都直接打开一场训练，标题、动作顺序和来源计划一致。两套计划含相同动作时，两个位置都能独立记组。
- [ ] **01.2** 从底栏验收单套直接开训、休息日和只有空计划时进入选择页、空计划与有动作计划同日时按原顺序合并。首页在休息日从当日覆盖选择计划，轮换队列行只开点中的一套。另从选择页启动其他计划及自由训练，从统计打开补录。
- [ ] **01.3** 给「主练」「辅助」的同一动作准备不同的上次正式组重量，并令两套各记一组。校验默认按计划查上次重量，另验没有同计划历史的回退。离线保存后 Web 按同一个训练 ID 读回一条记录，`routineIds` 顺序正确，两条动作各有自己的 `rid`。分别核对旧单计划草稿恢复、替换动作来源，以及轮换队列下一项与 Web 一致。

日程分流对照使用 Web 关闭训练前称重的配置，使入口直接进入训练。Web 的训练前称重分支在 `startFlow`。[开训前置条件](../../frontend/src/sheets.jsx#L3448)

## 03 收起与恢复训练

### 当前差异与代码位置

- **Web** 训练页左上角「收起」返回首页。草稿和休息计时继续，底部中央入口显示训练用时，点按返回原动作。计时组件挂在路由外，收起后仍可操作。[收起按钮](../../frontend/src/views/Workout.jsx#L2405) · [恢复按钮](../../frontend/src/components/TabBar.jsx#L46) · [全局计时条](../../frontend/src/App.jsx#L381)

### 修改目标与实施

1. 分开管理实时训练草稿与当前页面。训练页「收起」回首页，可切换其他 Tab。中央入口从原 `start` 计算用时，点击恢复原草稿。Android 返回键先处理外层面板或弹层，实时训练主页面的返回键执行收起。补录草稿沿用其原有返回和保存流程。
2. 训练页与常驻 Tab 页面都从同一份草稿读取休息和定位。收起时继续在 Tab 页面提供调时，避免两处各自计时。将动作位置随草稿保存，同一工作区冷启动可从原位置继续。旧草稿定位缺省时选首项，删改动作后校正定位。各开训入口和深链遇到未结束草稿时保留该草稿，账户切换只读取目标工作区的训练。[RN 草稿写入](../../mobile-rn/App.tsx#L176) · [工作区持久化](../../mobile-rn/src/storage.ts#L47) · [通知订阅](../../mobile-rn/App.tsx#L69)

- [ ] **03.1** 在第 2 个动作记一组后收起，能查看首页或其他 Tab。再点底部用时按钮回到第 2 个动作，已记组和剩余休息时间正确。

## 05 调节本次休息

### 当前差异与代码位置

- **Web** 底部计时条有 ±15 秒、暂停、继续、跳过。点时间能直接设置剩余时长。自然到点后显示「就绪」，可关闭或重新加时。[计时条与调时面板](../../frontend/src/components/RestTimer.jsx#L17) · [暂停和调时状态](../../frontend/src/store/useUI.js#L366) · [到点状态](../../frontend/src/store/useUI.js#L237)
- **RN** 倒计时按草稿中保存的 `endsAt` 更新，提供取消按钮，归零后收起。Android 到点通知也读取同一截止时间。[休息组件](../../mobile-rn/src/restTimer.tsx#L25) · [草稿计时字段](../../mobile-rn/src/training.ts#L236) · [通知排程](../../mobile-rn/src/restNotifications.ts#L25)

### 修改目标与实施

1. 计时条支持加减 15 秒、暂停、继续、设置剩余时长和跳过。上限为 900 秒。运行时打开调时面板，后台倒计时继续。直接确认原值保持现有状态，提交新值时以当前休息状态为准，设为 0 与跳过都关闭计时条。正常结束显示「就绪」，可以关闭或以 15 秒重新开始。[Web 上限](../../frontend/src/lib/duration.js#L8) · [设置剩余时长](../../frontend/src/components/RestTimer.jsx#L17) · [计时控制](../../frontend/src/store/useUI.js#L371)
2. 草稿中运行态由 `endsAt` 推算剩余时间，暂停态保存剩余秒数并冻结，可调时，继续时重算 `endsAt`。到期的运行态读成「就绪」，关闭后清除休息。旧草稿按原 `endsAt` 读取。已提交的运行态才向 Android 订阅传入到期时间。暂停、跳过、确认结束训练或放弃均取消排程，继续、加减时和就绪后重开按新到期时间排程。沿用当前通知在后台或锁屏可见的规则。[RN 通知排程](../../mobile-rn/src/restNotifications.ts#L25)

### 验收条件

- [ ] **05.1** 在 90 秒休息中分别操作加、减、点时间设置与跳过。打开调时面板等待几秒后原样确认，剩余时间继续流逝。测一次减到或设为 0 时关闭，以及加时在 15 分钟封顶。
- [ ] **05.2** 暂停后锁屏超过原到期时间，无旧提醒。返回调时并重启应用，暂停的秒数保留。继续后重新锁屏，开启 Android 通知时只在新的到期时间收到一次提醒。再次开一轮并跳过，过原到期时间无提醒。
- [ ] **05.3** 自然到点显示「就绪」。分别验证点关闭、从就绪按加 15 秒重新计时，以及锁屏回前台后读取正确的剩余时间或就绪状态。

## 06 结束、保存与查看本场摘要

### 当前差异与代码位置

- **Web** 点「完成」先打开结束面板，根据 0 组、部分完成、全部完成显示不同提示，可确认保存或选择放弃。勾完所有组还会出现完成或继续训练的提示。保存后打开本场摘要，展示时长、训练量、组数与新纪录，确认离开后回首页。[全部完成提示](../../frontend/src/sheets.jsx#L3864) · [结束面板](../../frontend/src/sheets.jsx#L4068) · [本场摘要](../../frontend/src/sheets.jsx#L4017)
- **RN** 至少完成一组且组数据有效时，点「完成训练」直接保存已勾选的组并跳到统计。放弃从训练菜单或底部操作触发确认。[完成条件及入口](../../mobile-rn/src/screens/WorkoutScreen.tsx#L122) · [保存和跳转](../../mobile-rn/App.tsx#L238) · [历史构建](../../mobile-rn/src/training.ts#L766)

### 修改目标与实施

1. 对实时训练增加结束面板。0 组显示「尚未记组」并可确认保存，部分完成显示未完成组数，全部完成给出保存确认。点放弃后单独确认，关闭面板可继续训练。最后一个未完成组首次勾上时提供完成与继续入口。勾选组仍须通过数值和分段校验，无效时定位到相应组，等用户更正后再保存。
2. 同时调整 `WorkoutScreen` 的结束条件和 `training.ts` 的历史构建，放行确认后的零组实时训练并保存 `entries: []`。部分完成时移除无任何已完成组的动作，留下的动作保留原组顺序和未勾选行（`done: false`）。保存 `routineIds`、兼容 `routineId` 和条目 `rid`，清理落单的超级组标签。统计、纪录和进度只消费已完成工作，历史详情、离线回传和 Web 读回均覆盖空记录及部分完成记录。[RN 结束条件](../../mobile-rn/src/screens/WorkoutScreen.tsx#L119) · [RN 历史构建](../../mobile-rn/src/training.ts#L766) · [Web 历史构建](../../frontend/src/lib/finish-workout.js#L69) · [RN 空记录展示](../../mobile-rn/src/screens/StatsScreen.tsx#L133)
3. 用一次 `gym.change` 提交同一训练 ID 的记录和草稿清理。已配对写入待同步队列，练习模式写本机历史。提交前防止重复确认。成功后撤销休息通知并展示摘要，关闭回首页。本地写入失败时留在训练，保留原草稿和计时供重试。已经本机保存的记录遇到同步失败时保留队列，后续用同一 ID 重试。[当前保存入口](../../mobile-rn/App.tsx#L238) · [本地写入](../../mobile-rn/src/useGym.ts#L40) · [同步去重](../../mobile-rn/src/server.ts#L100)
4. 摘要用实际保存的 `start`、`end` 计算时长，`end` 对齐 `sessionEnd` 的长时间闲置规则。组数展示已完成总组与正式组。显示训练量按当前设置决定是否计入热身组和自重，持久化 `vol` 按 Web 默认口径。用保存前的历史比较负重 PR 和估算 1RM 新高，按 Web 规则分别展示，重量 PR 写入 `prs`。配对状态下比较历史包含去重后的待同步记录。[有效结束时间](../../frontend/src/lib/finish-workout.js#L39) · [训练量口径](../../frontend/src/lib/history.js#L806) · [摘要显示](../../frontend/src/sheets.jsx#L4017) · [保存前判定纪录](../../frontend/src/sheets.jsx#L4087)

### 验收条件

- [ ] **06.1** 分别验证 0 组、部分完成和全部完成。部分完成显示准确的未完成组数，关闭面板后可以接着记组。最后一组首次完成弹出完成提示，选择继续后可再加动作。非法已勾选组须更正后才能保存。
- [ ] **06.2** 用相同历史和设置对照时长、训练量、已完成组和正式组的数值，以及重量 PR 与估算 1RM 新高。分别以包含热身组和超过 20 分钟闲置的训练核对相应口径。关闭摘要回首页，统计能查到记录。确认保存的 0 组训练显示零组和零训练量。
- [ ] **06.3** 以动作 A 完成第 1 组、留第 2 组未勾选、动作 B 全未勾选为例，断网确认保存并重启。RN 有一条待同步记录，A 保留两行含原完成标记，B 缺席。重新联网手动同步两次，RN 与 Web 读到同一 ID 各一条，只有第 1 组计入统计。另复验零组记录可同步，以及放弃时历史条数维持原值、计时结束。
- [ ] **06.4** 同一确认操作连续触发只写一条记录。在开发构建中让该次 `saveLocal` 抛错，本机写入失败后仍停在训练，保持原草稿和休息状态，恢复写入并重试成功后才出现摘要。

## 07 编辑计划

### 当前差异与代码位置

- **Web** 新建计划时先生成可编辑的计划。名称直接提交，动作配置在各自确认后立即写入，退出编辑页即可看到结果。动作可用拖拽手柄调整顺序，拖拽以普通动作或整个超级组为移动单位。[创建入口](../../frontend/src/views/Plan.jsx#L429) · [即时保存](../../frontend/src/views/RoutineEdit.jsx#L365) · [动作配置与拖拽入口](../../frontend/src/views/RoutineEdit.jsx#L526) · [超级组排序规则](../../frontend/src/views/RoutineEdit.jsx#L34)
- **RN** 编辑器在本地保留名称和动作表单状态，点右上角「保存」时校验并提交整套计划。动作按表单当前顺序提交。[编辑状态](../../mobile-rn/src/screens/PlanEditorScreen.tsx#L149) · [提交逻辑](../../mobile-rn/src/screens/PlanEditorScreen.tsx#L181) · [App 持久化入口](../../mobile-rn/App.tsx#L415)

### 修改目标与实施

1. 点新建时用 `create: true` 一次写入新 ID、默认名和 `ex: []`，成功后按 ID 打开编辑器。允许清空动作列表并继续编辑。名称即时提交，空白名称使用 Web 的默认名规则。动作配置确认、增删和拖拽落定各自提交。无效输入留在表单，已提交的名称和动作仍可继续编辑。返回时提示尚未提交的无效内容。
2. 用计划 ID 查最新本机数据，名称只提交 `name`，动作操作只提交基于最新动作列表计算的 `ex`。按 Web 的插槽规则移动单动作或整个超级组，先移除源单元再计算插入槽位，取消拖拽或落回原位不提交。计划已移除时退出编辑并反馈。`gym.commit` 返回成功后更新已保存状态，失败时保留本次编辑供重试。同步按现有待同步变更顺序回放，回包后重放发送期间提交的变更。[RN 提交与离线队列](../../mobile-rn/src/useGym.ts#L54) · [同步回包](../../mobile-rn/src/useGym.ts#L101) · [计划变更应用](../../mobile-rn/src/profileChanges.ts#L304) · [Web 拖拽规则](../../frontend/src/views/RoutineEdit.jsx#L34)

### 验收条件

- [ ] **07.1** 新建空计划后返回列表，能用同一 ID 重新打开。添加动作、改名和确认正式组参数后直接返回，重开可见改动。输入无效组数时，本机和 Web 仍保留最后一次已确认的组数。
- [ ] **07.2** 在同一套计划里拖动普通动作和一个超级组，重开编辑器后顺序正确，超级组成员顺序与关联正确。开始训练时读取最新顺序。
- [ ] **07.3** 离线调整两次顺序，把计划名从 A 改成 B 再改回 A。重启后读取最终顺序和名称。用调试版延缓首次同步响应，在响应回来前再确认一项组参数。响应回来后 RN 保留新组参数，再同步一次，在 Web 核对同一计划 ID 和最终名称、组参数及顺序。

## 实现后的联合验收

1. 用独立 openGym 实例和测试账户。用 Web 录入计划、排程和历史，再把 RN 配对到同一账户，以此验收读写。Web 与 RN 的行为对照分别从同一份初始历史和设置起跑，避免先保存的一端影响另一端的 PR 和轮换。对照数据准备单套、多套、只有空计划、休息日、轮换、重复动作及含超级组的长计划。[实例启动](../SELF_HOSTING.md) · [配对规则](../MOBILE.md)
2. 每批实施后在仓库根目录运行 `npm.cmd --prefix .\mobile-rn run check`。用开发版做逐项交互和截图，计时与通知验收使用实际时钟，关闭深链的 `e2e=1` 冻结模式。现有 smoke/regression 用于复验训练、历史和 Tab 的已有路径，新增交互按本文编号在设备上操作并记录结果。[RN 视觉验收](../RN_UI_VISUAL_TESTING.md) · [核心回归脚本入口](../../archive/RN_ANDROID_EXECUTION.md#本轮开发)
3. 在 Android 真机走一遍「合并开训 → 记组并更正 → 调节休息 → 收起并恢复 → 结束看摘要 → Web 查记录」。通知开启时覆盖切后台和锁屏。断网场景先完成配对并同步初始数据，然后断开 RN 到实例的连接，确认统计显示「待同步」，重连后从 RN 设置点「立即同步」并在 Web 刷新。记录训练 ID、计划来源、组完成标记、下一次推荐以及计划最终顺序。
