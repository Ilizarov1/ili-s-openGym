# 02 计划分享

## 需求

用户从「计划」导出 openGym JSON 计划文件并通过 Android 分享，可选择别人发送的同格式文件进行预览和导入。导入新增计划副本，用户可明确选择是否采用文件中的周排程。

## 实现设计

- 复用上游 [`buildPlanBundle`、`parsePlan`、`mergePlan`](../../../frontend/src/lib/plan-share.js) 和 [文件契约](../../DATA_IMPORTS.md#sharing-a-plan)。导出当前的计划、周排程与被引用的自定义动作，输出由上游计划序列化函数生成的 JSON；用现有 Android 文件选取和分享能力。
- 预览显示计划数、动作数、排程天数、单位换算及找不到的动作。导入生成新计划 ID，按上游规则匹配自定义动作，保持超级组、热身、递减、休息暂停、计时和有氧设定。保留上游支持且解析成功的扩展字段。
- 采用分享排程时按上游语义替换每周排程，空白日成为休息日。默认采用「仅导入训练计划」。确认时将生成的 ID 和必要的排程操作一起提交，离线与 `409` 重试沿用该次 ID，减少重复副本。

## 执行步骤

1. 接计划页分享入口、JSON 导出与预览；用 Web 导出的计划核对字段、单位和异常文件，再接导入确认与同步。
2. 用可见模拟器和独立 API 双向导入 Web/RN 文件，按下表保存计划对照、排程和服务端结果。

## 验收目标

| 编号 | 前置条件 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| 1 | RN 有 2 套计划、周一/周三有安排，另有训练和体重历史 | 导出文件，检查 JSON 并在 Web 导入 | Web 显示两套计划和对应动作；JSON 包含计划和周排程，历史、体重和配对凭据未出现在文件中 |
| 2 | Web 文件含力量高级组、超级组、计时和自定义动作；RN 中已有一套同名计划 | 预览并确认仅导入计划 | 原同名计划仍有原 ID 和动作；导入副本用新 ID；按上游规则复用同名同部位自定义动作，组配置可打开 |
| 3 | Web 文件用 lb，含 100 lb 动作；目标 RN 为 kg | 导入并开始该计划 | 目标约 45.36 kg，原次数、时长和休息秒数可核对 |
| 4 | 目标已有周二、周四计划；文件只排周一 | 分别选择仅导入、确认采用分享排程 | 前者保留周二/周四；后者只在周一出现新计划，周二/周四变休息日 |
| 5 | 已配对且离线；文件混含一个未知目录动作 | 预览、确认，恢复网络并复试同步 | 预览明确未知动作跳过数；可用动作随副本写入；同一次确认最终只生成一份 |
| 6 | 错误 JSON、openGym 完整备份或取消预览 | 尝试从计划入口导入 | 显示格式提示或回到计划列表，现有计划与周排程可照常读取 |
