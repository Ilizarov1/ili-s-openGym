# 01 · 固定 RN 入口和行为基线

状态为设备部分通过：动作库选择、训练添加和索引 `0` 替换已验证；计划添加、收藏和分页待补。对应 [总设计 S1](DESIGN.md#功能契约)。基线表见 [BASELINE](BASELINE.md#设备验收记录)，证据见 [验收记录](ACCEPTANCE.md#模拟器验收2026-11-20)。

## 依赖与执行范围

- Windows PowerShell、仓库 RN 依赖、Android SDK、可用的专用 Android 模拟器。构建与装载按 [RN 视觉验收](../RN_UI_VISUAL_TESTING.md#21-准备-debug-apk)。
- 读取 [动作库](../../mobile-rn/src/screens/ExerciseLibraryScreen.tsx)、[计划编辑](../../mobile-rn/src/screens/PlanEditorScreen.tsx)、[训练入口](../../mobile-rn/src/screens/WorkoutScreen.tsx) 和 [App 回调](../../mobile-rn/App.tsx)。本项记录当前行为，后续共用搜索从这些入口接入。

## 执行步骤

1. 从仓库根目录用 `git rev-parse --short HEAD`、`git status --short` 记录基线，确认进行中的动作库或替换选择器改动。用 `adb devices -l` 确认专用模拟器序列号。安装该基线的 Debug 应用。
2. 使用 [现有 fixture](../../mobile-rn/scripts/ui-fixture.ps1) 或专用本地工作区准备一份可编辑计划、一个名称独特的自建动作和一份无已记组的训练草稿。收藏一个内置动作。记录用于回归的动作 ID、原训练第一项和初始动作数。
3. 分别从动作库 Tab、计划编辑、训练动作列表的添加入口和第一项训练动作的「搜索替换动作」进入。记录 `ExerciseLibraryScreen` 的调用方、是否传入 `onPick` 和目标动作索引。若替换入口并行开发，记录它当前的确认方式。
4. 为每条入口记录搜索、清除筛选、点选、取消的基线。另用能匹配超过当前一页的查询记录总数和加载更多后的 ID。输出一份随执行记录保留的基线表，包含入口、查询与筛选、期望回调、实际结果和证据位置。

## 测试验收标准

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| 01-A | 动作库 Tab 查内置和自建动作 | 两类动作都可见；现有详情或选择入口行为已记录 |
| 01-B | 计划与训练分别添加同一已知动作 | 各自只新增一项，所选 ID 正确；取消时数量相同 |
| 01-C | 替换索引 `0` 的未记组动作 | 仅第一个槽位变化，训练动作总数一致；取消时原槽位不变 |
| 01-D | 测试收藏、部位、器械、清除与加载更多 | 有可重放的查询和筛选数据，已记录总数、分页和原有选择结果 |

完成条件为 01-A 至 01-D 都有基线证据。入口与设计不一致时，先更新入口基线，再继续 [第 02 项](02_REUSE_WEB_SEARCH.md)。
