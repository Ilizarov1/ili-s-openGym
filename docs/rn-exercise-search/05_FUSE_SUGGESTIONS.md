# 05 · Fuse.js 候选兜底与集成验收

状态为已实现，自动化验收通过；设备已验证零结果候选、筛选池隔离、正常结果隐藏、训练添加和索引 `0` 替换。计划添加、工作区切换和断网耗时待补。对应 [总设计 S5](DESIGN.md#功能契约)。证据见 [验收记录](ACCEPTANCE.md#05--fusejs-候选)和[模拟器验收](ACCEPTANCE.md#模拟器验收2026-11-20)。

## 依赖与执行范围

- [第 02 项](02_REUSE_WEB_SEARCH.md) 的正常结果、[第 03 项](03_EXISTING_ALIASES.md) 的别名读取和 [第 04 项](04_COMBINED_FILTERS.md) 的候选池均已验收。
- Fuse.js 只加到 RN 的 [清单](../../mobile-rn/package.json) 和 [锁文件](../../mobile-rn/package-lock.json)。实现限定在 RN 搜索适配层和 [动作库页](../../mobile-rn/src/screens/ExerciseLibraryScreen.tsx) 的零结果区域。Web 原有相似结果与正常排序继续走现有逻辑。
- 需要 Android Debug APK、Metro、专用模拟器及固定工作区。界面按 [视觉验收流程](../RN_UI_VISUAL_TESTING.md) 截图。

## 执行步骤

1. 在当前支持的 RN 工具链上确定 Fuse.js 版本，`npm.cmd --prefix .\mobile-rn install fuse.js --save-exact` 解析并固定版本，确认包和锁文件变化。检查 Metro 能解析依赖。记录实际版本。[Fuse.js 官方匹配说明](https://www.fusejs.io/fuzzy-search.html)
2. 为当前筛选候选构造轻量索引，只提供中文名称、已保存别名和动作 ID。沿用第 03 项的别名来源。目录、工作区别名、自建动作或筛选变化时刷新；单纯打字时复用索引。可延迟到首次触发时创建。
3. 仅在查询有至少四个汉字、筛选池非空且共享搜索完整返回零条时执行匹配。用 `ignoreLocation` 做名称内部匹配，按当前目录正反例校准阈值和候选排序，按动作 ID 去重并截取前三。共享搜索的正常结果和计数分别保持自己的值。
4. 复用现有动作行呈现「你可能在找」，使用现有详情或选择交互。清空查询、出现正常结果、筛选或工作区变化时，用当前结果更新展示，避免显示之前的候选。匹配不到时走正常零结果状态。新视觉模式按设计系统约定先补画廊。
5. 验收先记录每个错词的正常结果数。优先验证「高位下啦」与 `1204` 所在的动作家族。如果共享检索已命中，用能稳定证明正常结果为零的错词和固定候选池补一条兜底样例。记录查询、筛选、正常结果数、建议 ID 和排名。最后在同一构建上完成四入口的选择与取消集成回归。

## 测试验收标准

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| 05-A | 查询可复现的一字错词，确认正常结果数为零 | 「你可能在找」出现，候选中包含样例目标，ID 无重复且最多 3 条，正常结果数仍为零 |
| 05-B | 输入可正常命中的中英文名称或别名 | 正常结果和顺序与第 02–04 项一致，候选区隐藏 |
| 05-C | 对可建议的样例打开排除目标的器械、目标肌群、单侧或仅收藏条件，再逐项清除 | 被排除的动作不会出现在候选；变更后只展示当前池的候选；没有候选时只有零结果反馈 |
| 05-D | 输入空查询、短词如「卧堆」和事先记录的无关长词；快速切换查询和工作区 | 空查询及短词不触发，所选无关长词仍为零结果，切换后无残留候选，索引不随每次输入重建 |
| 05-E | 从动作库 Tab 看候选详情，再从计划添加、训练添加和索引 `0` 的训练替换选中候选；重复操作并取消 | 各入口使用正确 ID 和原有提交逻辑。添加一次只新增一项，替换只改变目标，取消不提交 |
| 05-F | 断网后执行名称搜索、组合筛选和候选兜底 | 与在线状态使用同一份本地数据时，命中集合、顺序和选择结果一致。记录普通搜索及兜底首次和重复搜索的耗时与设备信息 |
