状态为已实现，V1–V5 与 V6 的三处入口回归已在专用 worker 模拟器通过；V6 的预设备选直接切换未改动，按静态核对；连续点击的单次提交由代码核对。基线 `42411be33`，配套 [设计文档](DESIGN.md)。从仓库根目录阅读 [AGENTS.md](../../AGENTS.md)，使用 PowerShell。验收环境为 Android 模拟器，使用可编辑的本地训练草稿，无需配对服务端。

## 实施顺序

1. **确认入口与回调。** 打开一份含动作的计划并开始训练，选第一项未记组的动作，从动作菜单进入「搜索替换动作」。确认看到截图结构与现有行、信息按钮行为。核对 [WorkoutScreen](../../mobile-rn/src/screens/WorkoutScreen.tsx) 的两个搜索替换入口，以及 [App](../../mobile-rn/App.tsx) 的 `replaceIndex`、`pickForWorkout` 和外层 Modal。若实际入口与此不同，先定位实际调用方并同步两份文档，再实施。产物为确认后的入口记录。
2. **接通替换模式与详情。** 在 App 的面板调用处传入模式。在 [ExerciseLibraryScreen](../../mobile-rn/src/screens/ExerciseLibraryScreen.tsx) 切换行布局，复用设计系统样式，让详情区、星标和加号独立；保留列表实例并接通详情关闭。将加号和 [ExerciseDetailScreen](../../mobile-rn/src/screens/ExerciseDetailScreen.tsx) 的确认按钮汇入同一选择逻辑，限制重复提交。产物为内置、自定义动作共用的替换流程。完成条件为 V1–V4。
3. **替换筛选入口图标。** 查阅 [图标注册表](../../mobile-rn/src/design/icons/icon-paths.tsx)，添加标准漏斗图标并仅在共享动作库页头引用。保留现有 `setFiltersOpen`、高亮与计数。产物为更新后的筛选入口。完成条件为 V5、V6。

## 模拟器验收

在 Android Studio Device Manager 启动一个模拟器，从仓库根目录运行 `adb devices -l`，确认仅所用模拟器在线。安装依赖并构建、安装当前改动的 Debug 应用。已有 SDK/JDK 时，从根目录执行：

```powershell
Set-Location .\mobile-rn
npm.cmd ci
npm.cmd run android
```

若未配置本机 SDK/JDK，或需要单独构建 APK，按 [RN 视觉验收的 Debug APK 准备步骤](../RN_UI_VISUAL_TESTING.md#21-准备-debug-apk) 配置。Metro 从 `mobile-rn` 启动。若设备未连接或安装失败，先恢复设备或修正构建环境，再开始记录验收；确认模拟器运行的是本次构建。

| 编号 | 模拟器操作 | 通过条件 |
| --- | --- | --- |
