# RN Android 首版设计

## 范围

交付可独立启动、可侧载的 Android APK。使用 Expo、React Native 和 TypeScript，应用 ID 为 `dev.opengym.rn`，可与官方客户端并存。首版提供训练计划、组数和重量记录、历史，以及通过现有 API 配对和同步。高级训练类型、媒体、手表和健康平台留待后续。

## 首版数据流

- `mobile-rn/` 独立构建。界面使用 RN 组件，计划、动作 ID 和训练记录沿用上游数据格式，动作名复用现有目录和中文翻译。
- SQLite 保存练习模式与各服务器账号的数据、进行中的训练和待上传记录。配对令牌放入 SecureStore。独立练习模式提供示例计划，使用单独的数据空间。
- 配对走 `POST /api/pair/redeem`，读取走 `GET /api/data`。只向服务器新增本客户端完成的训练。每次上传先取最新状态，按训练 ID 加入待上传记录，再携带 `baseRev` 和可用的 `baseWid` 提交。收到 `409` 后用最新状态重试，保留服务端其余字段。失败时保留待上传记录。
- 支持显式输入局域网 HTTP 地址，以兼容自托管实例。默认补全 HTTPS，HTTP 配对前在界面标明传输方式。

## 验收

APK 内置 JS。独立模式可完成一次训练并在重开后看到历史。配对后可读取服务端计划，离线完成的记录可在恢复连接后同步。同步重试按训练 ID 去重。

## P1 手机端管理

- **离线编辑**。训练修改、计划、自定义动作和排程先落 SQLite。同步时对最新服务器状态应用待同步操作，使用原有修订号检查。补录沿用训练记录格式，训练日期与同步修改时间各自保存。
- **排程与训练**。沿用 Web 的周排程、轮换和今日计划计算。动作库复用上游目录和中文名，计划同时支持力量、有氧和计时。
- **恢复与合并**。导出计划、动作、排程和历史的 JSON，包含待上传记录。导入按 ID 添加缺失数据，保留当前记录，按目标账号的单位转换重量。练习模式和账号的数据仍保存在各自空间。
- **到点通知**。用户开启组间通知后，Android 根据草稿中的结束时间安排通知。修改或取消休息、结束训练时更新或撤销计划通知。精确触发取决于系统的闹钟权限。

## P2 超级组

- **组关系**。计划编辑和训练中均可组合或拆开相邻动作。训练中可在相关动作记组前调整。使用上游的 `sg`、`sgName` 和 `sgRest`，替换动作时沿用原槽位的组关系。
- **记组**。热身先完成，正式组按动作顺序轮流记录。组数不同就跳过做完的动作。组内切换直接进入下一动作，轮末用组间休息设置，未设时使用成员中最长的休息。普通动作沿用当前计时规则。
- **持久化**。根据草稿里已完成的组恢复下一步，继续使用 SQLite 和现有同步接口。历史中的 `entry.sg` 与计划格式保持兼容。
