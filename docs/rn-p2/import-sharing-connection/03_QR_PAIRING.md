# 03 二维码配对

## 需求

用户在已登录网页端生成移动端配对码后，可用 RN 设置页扫描二维码。手机显示服务器地址，用户确认后为当前工作区连接账号，手动地址和配对码入口同时可用。

## 实现设计

- 当前 [网页移动端配对面板](../../../frontend/src/components/Passkeys.jsx) 显示一次性文本码。拟在同一 `PairSheet` 用现成 `QrCanvas` 显示 `opengym://pair?server=<编码后的基础地址>&code=<配对码>`，带上实际反代子路径。网页「添加另一设备」的登录 QR 继续使用各自的接口。
- 在 [SettingsScreen](../../../mobile-rn/src/screens/SettingsScreen.tsx) 点「扫描配对二维码」才请求相机权限。只扫 QR，解析指定 scheme/path、两个唯一参数及上游 8 字符配对码，地址经现有 `normalizeServer`。扫码填充确认页，点击确认后才走 `connect`，每次确认只调用一次。[Expo Camera](https://docs.expo.dev/versions/v55.0.0/sdk/camera/)
- 沿用 [`POST /api/pair/create` 与 `POST /api/pair/redeem`](../../../api/openapi.yaml) 的单次、5 分钟有效期。成功后通过 `useGym` 与 SecureStore 接入原账号工作区，失败可回填或重扫。配对码仅用于扫描、确认和兑换，日志和截图用脱敏 fixture。

## 执行步骤

1. 先接网页二维码生成、RN 纯解析器和表单确认，验证格式、重复扫码及服务器地址规则，再通过 Expo SDK 55 接相机并重建 Android。
2. 在独立 API 用两个账号和可见模拟器走完整配对；用 Android 真机扫同步生成的 QR。按下表记录配对请求次数、工作区读回和权限结果。

## 验收目标

| 编号 | 前置条件 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 独立实例签发有效移动端码，HTTPS 实例带反代子路径 | 真机扫描、检查地址、点确认 | 确认前 API 没有兑换请求；确认后仅一次请求打到正确子路径，当前账号计划可读回 |
| 2 | 有同一有效码的 QR 持续在取景框，另有一种局域网 HTTP 地址 | 反复扫描，分别取消和确认 | 扫描只打开一份确认页；取消不耗码；HTTP 局域网显示现有提示后可确认 |
| 3 | 发放码已过期、已兑换或被重新生成替换 | 分别扫码并确认 | 现有错误提示引导重新生成；失败时旧连接和其数据可读回 |
| 4 | 设备登录二维码、普通 URL、重复参数、无效码或公网 HTTP | 分别扫码并查看 API 访问信息 | 确认入口拒绝不匹配的格式或地址，兑换请求数为 0 |
| 5 | 相机权限拒绝或恢复 | 拒绝时手动配对，再授权后重新扫一扫 | 手动流程可成功；重新授权可扫；离开扫描页相机预览关闭 |
| 6 | RN 已连账号 A，准备了账号 B 的有效码 | 先取消，再扫码确认 B；重开 App | 取消时仍为 A；确认后只读到 B 的工作区；重开连接仍有效，A 的历史可在后续切回时读取 |
