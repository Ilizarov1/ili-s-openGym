# 01 第三方历史导入

## 需求

用户从「设置 → 备份与数据」选择第三方训练历史文件，看到来源、有效训练与组数、单位、自动匹配及新建动作、跳过原因，确认后合并到当前工作区。文件范围按 [上游训练历史导入](../../DATA_IMPORTS.md#workout-history-from-another-app)，覆盖有训练记录的 CSV/JSON 导出及上游可识别的自定义 CSV。

## 实现设计

- 用现有 Android 文件选择和文件读取能力，沿用 RN 备份的 20 MiB 读取上限。复用 [`parseImportFile`](../../../frontend/src/lib/import-apps.js) 与 [`mergeImport`](../../../frontend/src/lib/import-csv.js) 的训练分支。预览阶段仅解析并计算合并结果，只有确认后才保存。按类型给体重文件、仅计划文件和 openGym 备份提示对应入口。
- 按上游规则以本地训练日期去重，已有该日记录时跳过该日的导入；空白日可带入多场。以实际保留的训练为准生成或复用自定义动作，沿用上游匹配及单位规则，保存原训练日期、完成组与评分等字段。
- 已配对时将确认的导入意图与确定的 ID 持久化，重连时基于最新工作区重新判断该日是否可导入。一次合并写入训练和用到的动作，再由现有同步链路发布。预览和提交之间发生冲突时，反馈实际导入和跳过数。

## 执行步骤

1. 为对外声明的每个来源准备脱敏文件。用上游解析器对照类目、训练数、组数、单位和日期，补文件大小、破损与取消场景。
2. 接预览、确认与离线提交。用可见模拟器和独立 API 执行下表，保存预览与结果截图、API 的训练和动作 ID 及条数。

## 验收目标

| 编号 | 前置条件 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 有 FitNotes Android、FitNotes 2、Strong、Hevy、Gravl、Liftosaur、Liftoff、StrongLifts、Fitbod、JEFIT 及通用 CSV 的训练样本 | 逐份选择并核对预览后确认 | 每份来源、训练/组数、日期、匹配和未匹配计数与上游解析结果一致；Liftosaur 的历史 CSV 与含训练的 JSON 均覆盖 |
| 2 | kg 账号；一组为 100 lb×5，另有评分或有氧时长 | 确认导入并查看历史和 API | 重量约 45.36 kg、次数 5；支持的评分、时长和完成标记可读回 |
| 3 | 文件含两个日期，各两场；当前账号已有其中一天的训练 | 确认一次，再重复导入同文件 | 首次跳过已有日的两场，添加空白日两场；第二次新增 0；已有训练和计划可读回 |
| 4 | 一个未知名称与账号已有自定义动作同名，另一个从未见过 | 从空白日导入，查看动作库与历史 | 同名引用已有动作 ID；新名称创建一个动作且训练引用该 ID；被跳过的训练不会多出动作 |
| 5 | 预览后离线确认；重连前 Web 已写入其中一个日期 | 重连并模拟 `409` 后回读 | Web 在该日新增的训练保留、该日导入被跳过；实际数量有反馈，重试只写一次 |
| 6 | 损坏文件、只有列头、超过读取上限、类型不符或预览后取消 | 分别尝试导入 | 有对应反馈；取消回原页；统计、计划和 API 无新增条目 |
