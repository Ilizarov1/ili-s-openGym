## 1. 模块与代码落点

| 设计落点 | 职责与现有边界 |
|---|---|
| `api/agent-runtime/` | 共享 JS ESM 运行核心，定义任务、上下文、工具派发、结果校验与状态转换。只通过注入接口访问平台能力。放在 API 构建目录内，便于现有镜像把源码编入 `dist`。 |
| `mobile-rn/src/agent/` | 提供 RN 执行器、SQLite 仓储、SecureStore 配置与远程模型请求。业务读取沿用 [RN 工作区](../../mobile-rn/src/storage.ts) 的作用域规则。 |
| `api/src/agent/` | 提供 NestJS 模块与会话鉴权入口，接入账号数据、配置存储、作业状态及启动恢复。沿用 [CoachController](../../api/src/coach/coach.controller.ts) 的鉴权与 [CoachService](../../api/src/coach/coach.service.ts) 的生命周期接入方式。 |
| `api/coach/core/` | 参考已有的 provider、结构化输出和提案校验。经两端构建和兼容性验证后复用可移植部分。 |

现有 Coach 作业以 Coach 任务和提案为中心，现有路由继续由原模块处理。新模块的运行记录以独立 run ID 寻址。共享核心使用平台无关接口与声明文件，Metro 显式加入共享目录，API 构建验证 `dist/agent-runtime` 及依赖。相关入口见 [Metro 配置](../../mobile-rn/metro.config.js)、[API 构建脚本](../../api/scripts/build-api.mjs) 和 [API Dockerfile](../../api/Dockerfile)。

## 2. 运行契约与上下文（R1、R2）

| 契约 | 字段与责任 |
|---|---|
| `RunRequest` | `taskId`、`requestId`、`profileId`、`input`、可选 `sessionId` 和 `attachmentIds`。调用端先选择本机或服务端入口，入口确定实际执行位置。 |
| `TaskDefinition` | 输入和输出 schema、模型能力要求、上下文字段投影、必要事实、执行步骤、步骤工具列表及调用预算。任务由宿主注册。 |
| `RunContext` | 执行方绑定的账号或工作区、`runId`、任务与配置版本、数据视图、证据映射、截止时间与取消信号。调用方传来的所有 ID 都在绑定后的作用域内解析。 |
| `ModelInput` | 应用指令、用户内容块、事实与记忆投影、当前步骤工具描述、最近一轮工具结果。附件经平台适配解析后作为图像输入。 |
| `RunResult` | 通过任务 schema 的结果及证据引用，或结构化提案。错误返回稳定错误码和可展示信息。 |

一次运行的顺序为 **绑定作用域 → 核对配置和输入 → 读取必要事实 → 组装模型输入 → 执行步骤 → 校验并保存终态**。事实携带对象 ID、来源、版本或内容摘要。对模型发放运行内证据 ID，结果返回后在映射表中解引用。工具读取追加来源和实际读到的版本，形成新证据，已有证据继续关联原版本。提案生成与应用之间使用目标版本检查。

任务给输入文本、附件、工具结果和轮次设硬上限。上下文优先保留应用指令、当前输入、必要事实和当前工具结果，先裁剪可选历史和记忆。必要内容仍超限或缺失时返回明确错误。工具输出和历史内容作为数据块传入。媒体适配只解析本机已登记文件或当前账号可访问的服务端媒体引用，验证 MIME、大小和实际格式，日志只记媒体元数据。新上传入口随业务需求设计。

## 3. 模型接入和凭据（R1）

`ModelGateway.invoke(profileRef, modelInput, signal)` 返回规范化的文本、结构化对象或工具请求。配置解析区分本机用户、服务端默认、服务端用户三类，均生成包含配置 ID 和版本的引用。任务调用前校验配置能力，发请求前复查配置有效性。配置变更或删除后，后续模型请求以明确错误结束，用户可重新发起。

- 本机在 SecureStore 保存凭据，SQLite 保存配置元数据。服务端默认配置沿用现有管理员配置入口，接入前核对其可用模型和版本标识。
- 服务端用户配置按账号保存。使用服务端独立环境密钥做凭据认证加密，密文包含随机 nonce、认证标签和密钥版本，账号、配置 ID 与版本参与认证。加密密钥缺失时明确禁用服务端用户配置，应用重启后可用原密钥解密。接口写入后只回传脱敏信息，日志排除密钥和请求正文。
- 首期服务端用户可以选预设提供商和模型并填写自己的密钥。服务端端点由提供商表或管理员配置决定。本机用户自定义远程端点时通过 HTTPS。服务端开放用户自定义端点需另行定义出站地址策略。
- 首期使用有界的完整响应，模型接入验收覆盖文本、图像请求构造和工具请求归一化。真实供应商兼容性单独记录。

## 4. 工具与安全围栏（R3、R4）

共享工具定义包含 ID、描述、参数 schema 和返回 schema。平台实现接收可信的作用域与取消信号。固定步骤由代码调用已有读服务。需要模型选择工具时，由当前步骤显式列出工具 ID，模型请求统一走派发器。

**工具调用围栏。** 派发器依次检查当前步骤允许列表、参数结构、调用次数、目标与任务范围，然后调用只读实现。访问对象前检查归属和业务范围，例如真实 ID 也必须属于当前任务允许的目标集合。校验失败返回稳定的拒绝原因，底层工具调用计数应为零。工具返回通过结构校验并按任务投影后进入下一轮。

**业务写入围栏。** 模型输出由应用转换为不可变提案，保存 `proposalId`、改动内容、任务范围和目标版本。确认请求只接受已展示的提案 ID，服务端或本机从存储读取原提案。业务适配器在同一原子写入中检查当前状态与版本、应用改动并记录已消费提案 ID。重复确认返回原结果，目标已变化返回冲突。首期用桩业务适配器证明这一契约。真实写入口需要证明原子性后再注册。

模型接入层负责发请求，数据访问层负责绑定身份。围栏只检查模型请求可能触发的工具和写入动作。

## 5. 记忆与持久化（R5）

- **运行记录**保存状态、时间、配置和数据版本、校验后的结果或提案，以及错误码。完整 prompt、工具原始输出和临时媒体读取数据保持在运行内，终态后释放。运行记录保留至显式删除或未来定义的清理策略。
- **会话**按作用域与会话 ID 保存用户可见消息。首期按消息顺序取最近记录并遵守任务预算。摘要如启用，作为可删除的会话派生记录。运行开始时取得会话版本，删除会话后，仍在执行的任务不得把结果写回已删除的会话。
- **长期记忆**保存 `id`、类别、值、来源、更新时间与版本。由用户确认后写入，按任务声明的类别筛选，优先取最近更新内容。编辑与删除影响下一次组装，已发送的请求保留其当时使用的版本。业务事实由原训练数据层提供。
- RN 用 SQLite 保存 Agent 独立记录，按现有工作区键查询。服务端首期在现有持久化目录下按账号保存 Agent 数据，复用 [原子写入器](../../api/src/common/persistence/atomic-write.ts)，以账号为粒度串行执行读改写。服务端首期按单写入进程部署。记忆和运行记录归属执行环境。

## 6. 作业接口与运行状态（R6）

RN 调用面统一提供 `start`、`get`、`cancel`。NestJS 在现有 API 路径前缀下提供 `POST /agent/runs`、`GET /agent/runs/:runId` 和 `POST /agent/runs/:runId/cancel`。配置、会话和偏好的读写由所属模块提供。服务端通过现有请求解析约定读取有界 JSON，并同步维护 OpenAPI。

`accepted -> running -> completed | failed | cancelled | interrupted`。已接收且尚未执行的作业也可取消或标记中断。终态只写入一次，结果与完成状态原子提交。取消先提交状态再触发中止信号，模型或工具晚到时丢弃结果。作业终态和会话持久化分别校验对应对象的有效性。

服务端以账号和请求 ID 去重，在发起调用前持久化请求指纹与 run ID。相同输入返回原作业，复用请求 ID 但输入不同返回冲突。断线只影响查询，用户可以携带 run ID 继续查询。应用重开或服务端启动时，将本执行环境遗留的非终态作业标记中断。用户主动发起新任务时生成新请求 ID。
