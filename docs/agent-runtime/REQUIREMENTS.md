# openGym Agent 运行环境需求

## 目标与范围

面向 RN Android 和 NestJS，建立可供多模态检索、智能训练指导复用的运行环境。本期定义执行方式、上下文传递、工具提供、安全围栏、记忆和运行状态。业务功能的交互、检索算法、训练指导规则与模型选型留给各自的设计。

## 运行环境架构图

```text
                         RN 界面
                 选择执行位置和模型配置
                            |
          +-----------------+------------------+
          v                                    v
     本机执行（RN）                       服务端执行（NestJS）
     绑定当前工作区                       绑定当前登录账号
     读取本机数据和未同步记录             读取服务端可用数据
     手机保管用户 API 凭据                服务端保管默认或用户 API 凭据
          |                                    |
          +------ 共用运行协议，各自执行 ------+
                            |
                            v
                       运行上下文
          身份、配置引用、数据版本、工具范围、取消信号
                            |
                            v
  本次输入和附件 --------> 组装本轮模型输入 <----- 业务数据、会话历史、
                            |                    用户确认的长期记忆、
                            |                    上一轮工具结果
                            |
                            v
                  模型 API 适配层 -> 远程模型 API
                                       |
                                       v
                                    模型输出
                                       |
             +-------------------------+-----------------------+
             v                         v                       v
        工具调用请求                业务变更提案              普通结果
             |                         |                       |
             v                         v                       v
        围栏 1 检查工具、           围栏 2 校验提案、          校验后返回
        参数和目标                  展示改动、等待用户确认
             |                         |
             v                         v
        应用执行只读工具            业务层复查目标和版本
        结果进入下一轮上下文        通过现有入口写入
```

固定流程可由应用直接调用只读工具。模型需要自主选择工具时，只能从当前步骤开放的工具中发起请求，调用通过围栏 1 后才执行。

运行状态和记忆由执行环境保存。本机按工作区隔离，应用退出后可识别中断。服务端按账号隔离，客户端重连后可查询原作业。

## R1 执行方式与模型配置

用户可以选择本机执行或 openGym 服务端执行。两种方式均调用远程模型 API，因此模型任务需要联网。执行位置和模型 API 的来源独立配置。

| 执行位置 | 模型 API 配置 | 数据范围 |
|---|---|---|
| 本机 | 用户配置，凭据保存在设备安全存储 | 当前 RN 工作区，可读尚未同步的数据，无需配对 |
| 服务端 | 管理员默认配置，由服务端保管凭据 | 已认证账号的服务端数据 |
| 服务端 | 用户提供配置，由服务端按账号加密保管凭据 | 已认证账号的服务端数据 |

- 启动任务时固定执行位置和配置引用。连接或模型调用失败时展示原因，用户可主动选择另一方式重新发起。切换执行方式时无自动任务转发或凭据迁移。
- 服务端向客户端返回配置标识、脱敏信息及可用能力。模型适配层根据所选配置校验文本、图像等请求能力，并统一处理超时、取消和提供商错误。若允许服务端用户填写自定义 API 地址，由服务端出站层限制可访问的目标。

## R2 上下文传递

| 上下文 | 由谁构造 | 内容 |
|---|---|---|
| 运行请求 | 调用方 | 任务类型、用户输入、执行方式、配置引用，以及可选的附件和会话引用 |
| 运行上下文 | 所选执行环境 | 可信工作区或账号、配置引用、数据来源与版本、当前步骤允许的工具及取消信号 |
| 模型输入 | 任务上下文组装器 | 任务指令、用户输入、任务声明所需的事实、附件、相关记忆，以及当前步骤的工具说明和结果 |

- RN 从当前工作区绑定身份，NestJS 从已认证会话绑定身份。运行环境在该范围内解析请求中的记录、附件、配置和会话引用。
- 业务事实带来源标识。可变对象带可用的版本或等价快照标识。模型结果中的证据引用由运行环境映射回实际对象。
- 任务决定哪些字段和附件可以发送到模型。输入超出预算时优先裁剪可选历史和重复片段，缺少必要事实时返回可解释的状态。凭据由模型适配层注入请求，留在模型输入和运行记录之外。

## R3 工具提供

- 工具定义包含稳定名称、用途、输入与输出结构。RN 和 NestJS 可为同一工具提供不同实现，业务参数和返回约定共用。
- 固定流程由任务代码调用类型化工具。确需模型选择工具时，仅暴露当前步骤需要的工具，并给该步骤设置调用上限。
- 工具由应用执行，处理器从可信运行上下文获取账号或工作区。模型提供业务参数；执行器依据任务规则解析目标和调用范围。

## R4 安全围栏

安全围栏位于模型输出到应用执行之间，负责拦截模型幻觉造成的错误工具调用和意外业务修改。数据隔离属于数据访问层，密钥和网络请求属于模型接入层。

1. **工具调用校验。** 执行前检查工具是否允许在当前步骤使用、参数是否符合 schema，以及目标是否存在且符合本次任务范围。即使参数合法，当前步骤不允许的调用也应拒绝。拒绝时返回可识别的错误，工具不执行。
2. **业务写入确认。** 模型只生成结构化变更提案。运行环境校验改动结构和目标，用户查看并确认具体改动后，由现有业务写入入口核对对象、当前状态和版本。目标已变化时提示重新生成，重复确认只应用一次。

首版以这两处执行检查为围栏。没有开放模型工具调用的步骤，由应用代码直接读取已知数据并校验模型结果。

## R5 记忆管理

| 类别 | 首版要求 |
|---|---|
| 运行状态 | 用于记录本次执行与查询结果。临时上下文按保留策略清理。 |
| 会话历史 | 保存用户可见的消息和结果，按需选入最近消息或摘要。删除会话时一起删除派生摘要。 |
| 长期记忆 | 用结构化记录保存用户确认的偏好、目标或约束，保留来源与更新时间，支持查看、编辑和删除。模型只能提出保存建议。 |
| 业务事实 | 从训练记录、计划和目录读取。模型生成的摘要可用于上下文组装，业务记录仍是事实来源。 |

本机记忆按工作区隔离，服务端记忆按账号隔离。切换执行方式时使用所选环境中可访问的记忆。跨设备记忆同步及语义召回留待有明确需求时设计。

## R6 运行状态

- 每次运行有独立 ID 和可查询的终态，区分完成、失败、取消和中断。记录执行位置、配置引用、数据来源与版本、耗时及错误类别。
- 本机先按前台运行设计，进程退出后可识别中断，并保留已完成结果。服务端作业支持客户端断线后查询，同一提交请求重试时返回原作业。
- 取消后到达的模型结果不得覆盖终态或产生可应用的提案。服务端进程重启后可标记中断，首版恢复范围为状态与已保存结果。

## 首版验收

使用可控的模型与工具替身验收基础设施，无需接入真实业务流程。

| 对应需求 | 场景 | 预期结果 |
|---|---|---|
| R1 | 分别使用本机用户配置、服务端默认配置和服务端用户配置启动任务 | 各自在选定环境执行，只使用所选配置。模型不可用时返回错误，任务不会自动换环境。 |
| R2 | 提交其他账号的引用、超预算历史及当前工作区未同步数据 | 越权引用被拒绝，可选历史按规则裁剪，本机可读取未同步数据，服务端使用其可访问版本。 |
| R3、R4 | 模型返回未开放工具、错误参数、越界目标或当前步骤不允许的调用 | 工具均未执行，记录能辨别拒绝原因。 |
| R4 | 未确认、重复确认或目标已变化时提交提案 | 未确认无写入，重复确认只应用一次，目标变化后拒绝应用。 |
| R5 | 保存偏好后切换账号或工作区、删除原记录 | 其他范围无法召回该偏好，删除后不再进入后续上下文。 |
| R6 | 服务端提交响应丢失并重试，或取消后模型才返回 | 重试找到原作业，晚到的结果不改变取消状态。 |
