# AI 动作检索（多模态）需求

[Agent 运行环境](../agent-runtime/REQUIREMENTS.md) 的第一个业务消费者。状态为需求、交互与技术设计已修订，[执行计划](EXECUTION.md) 已成文待执行。

Web 与 RN Android 同批交付。本文记录交互契约、需求边界和编号验收条件；技术设计见 [DESIGN](DESIGN.md)。实施前置为 agent-runtime 基础设施按其[执行计划](../agent-runtime/EXECUTION.md)先行验收。

## 目标与范围

在动作库和训练动作选择流程内提供大模型多模态检索：用户用**纯文字描述、单张图片、或图+文组合**表达想找的动作，模型理解语义后返回动作库候选；不满意时在同一会话内**追加文字或图片继续细化**，每轮返回新候选。

典型场景是用户看到一个不认识的器械，拍照后想**把它加入自己的训练**，或在训练中**替换已有动作**。AI 只负责识别和检索，加入/替换沿用现有动作详情、计划编辑和训练选择器的写入路径，不新增 AI 直接写训练数据的入口。

- 客户端范围：RN 动作库 Tab、训练中的添加/替换动作选择器；Web `Library` 页、Web 动作选择器。Web 仅服务端执行；RN 本机与服务端均可（沿用 agent-runtime R1）。
- 输出始终是**动作库候选 + 兜底建议**双通道，不做自由问答、不生成训练计划、不直接修改训练数据。
- 关键词检索（现有搜索引擎和 Fuse 建议）行为保持不变，AI 检索是并列的新入口。
- 选择候选后沿用调用方原有语义：动作库进入动作详情；训练选择器直接返回动作或打开现有配置面板。

## 用户场景

| 编号 | 场景 | 示例 |
|---|---|---|
| U1 | 纯文字描述检索 | "坐着往上推的器械，肩膀不适想找替代" |
| U2 | 纯图片检索 | 拍一张不认识的器械照片 |
| U3 | 图 + 文检索 | 器械照片 + "只有哑铃，想找类似的" |
| U4 | 会话内追问 | 候选不满意 → "不是，是坐姿的那种" → 新候选 |
| U5 | 追问补图 | "再拍个角度"，追问输入行直接带图发送 |
| U6 | 无匹配兜底 | 模型对输入的理解描述 + 建议身体部位/器械筛选 |
| U7 | 无法发起 | 未配置模型 / 服务端禁用 / 图片超限或格式错误 |
| U8 | 训练中拍照替换或添加 | 训练中打开替换选择器，拍下器械，选中候选后替换原动作；或从选择器加入新动作 |

## 需求条目

### R1 入口与输入面板

- RN 在 `SearchField` 内渲染附加入口按钮（设计系统组件新增可选回调，传入才渲染），`sparkles` 图标，`accessibilityLabel="AI 检索动作"`；动作库 Tab 与训练添加/替换选择器共用该组件。
- Web 在 `Library` 搜索框旁和 `ExercisePicker` 搜索行提供同等入口；选择器内的 AI 检索以覆盖层替换列表内容，不再叠加第二个 Sheet。
- 输入面板用 Sheet：多行文字输入（回车换行，发起只走按钮）；"拍照"与"从相册选择"并排按钮，各直调 `expo-image-picker`，不做二级弹层；单张图片，选第二张替换第一张并提示；缩略图可移除。
- "AI 检索"按钮在文字或图片至少一项时可点；面板含 footnote"使用 AI 模型识别，需联网"。
- placeholder 引导带约束的描述：`描述想找的动作或器械，可加上你的条件（如：肩膀不适、只有哑铃）`。
- 不新增依赖：`expo-image-picker`、`expo-image-manipulator`、`expo-image`、`expo-file-system` 均已在 RN 依赖中。

### R2 发起与运行

- 发起后面板收起，动作库/选择器列表区进入**独占识别态**：清空文字查询、隐藏筛选 chips、忽略进入前的关键词与筛选；摘要卡（最新输入的文字摘要 + 可选缩略图 + 取消）置顶，后续内容替换原列表。
- 识别态内搜索框仍在位，文字输入禁用，`sparkles` 保持可用；点 ✨ 打开面板并取消当前运行，发起新请求。
- 运行绑定页面/选择器生命周期：离开动作库页、关闭选择器或离开当前 Tab 即取消；服务端按 agent-runtime R6 提交取消状态并丢弃晚到结果；动作详情往返不退出识别态。
- 选择器内选中候选后先按现有选择器语义提交，再退出识别态并关闭选择器；AI 不新增确认层或写入路径。

### R3 结果与兜底

- 候选最多 5 条，每条含 `MediaThumb`、动作名、识别或匹配依据（footnote）、匹配等级 Badge（高/中/低，不用百分比置信度）。
- 动作库 Tab 的 AI 候选点选进入动作详情，详情继续提供现有的加入计划/开始训练入口；从详情返回后结果区保持。选择器点候选按 R2 的调用方语义返回。
- 模型输出的兜底通道（对输入的理解描述 + 建议身体部位/器械筛选）**总是返回**，与候选并存。
- 无候选时直接显示兜底区；有候选时经尾部轻量入口"都不对？继续追问，或看看建议筛选"展开。
- 兜底区建议筛选 chips 点击后：清空文字查询、清空其他筛选、应用该 chip 对应维度（身体部位或器械）的建议值，退出识别态。此路径**不恢复**进入前的筛选快照，避免旧文字/筛选把建议结果再次过滤掉。
- 点摘要卡 `x` 退出识别态：恢复进入前的文字查询与筛选快照；会话删除、图片删除。

### R4 会话式追问

- 识别态底部常驻单行追问输入行：`[📷] [文字输入] [可选缩略图] [发送]`；发送条件文字或图片至少一项（纯图追问即"补个角度"，合法）。
- `📷` 弹小 Sheet 选"拍照 / 从相册选择"（页面层弹层，无 Sheet 嵌套）；缩略图发送后清空。
- 每次追问 = 新 run（新 requestId）复用 `sessionId`；首轮创建会话。**替换式**呈现：摘要卡与候选始终显示最新一轮，历史仅在模型上下文中（按 agent-runtime R2/R5 组装与裁剪）。
- **首轮固定执行位置**（RN 本机或服务端）和模型配置解析范围；追问只允许在同一执行环境内重新解析配置，不自动切换到另一执行端。缺少图像能力时返回 `profile_capability_missing`，并提供"在另一执行端重新发起"的明确操作，不静默丢历史。
- 追问运行中：输入行禁用、发送变 spinner、旧候选保持可点；可取消该轮，取消后输入行内容保留、候选停在上轮。
- 追问仅细化检索：每轮返回新候选 + 兜底，不做自由文字问答。
- 首轮之后最多 5 轮追问（即每个会话最多 6 个 run）；客户端到限后禁用输入行并提示重新发起；服务端按 task + session 计数并返回 `turn_limit`，防止绕过客户端消耗默认密钥。
- 同一会话同时只允许一个运行中的 run；新 run 前客户端取消旧 run，服务端遇到并发返回 `session_busy`。
- 退出识别态 = 取消运行并删除会话；运行中的追问不写回已删会话（agent-runtime R5 守护）。
- 会话内图片预算：客户端保留最近 2 张图（当前轮新图在前、上文图在后）随请求重发，更早图片丢弃；图片只存客户端，会话消息只存张数/字节/MIME/尺寸等元数据。

### R5 执行位置与模型配置

- **静默解析**：发起与追问均使用默认配置解析，不在检索流程暴露执行位置概念。
- 首轮解析顺序：RN 本机可用配置 > 服务端用户配置 > 服务端默认配置；练习模式仅本机。Web 仅服务端用户配置 > 服务端默认配置。同一层按配置 ID 升序取第一个可用配置，保证可复现；摘要卡 footnote 显示所用配置的脱敏名称。
- 首轮把执行位置固定到会话；后续追问只在同一执行位置内解析配置，不自动换端。
- 能力校验按该轮实际输入：纯文字只需 `text`，带图必须 `image`；缺失返回 `profile_capability_missing` 的可展示文案。首轮纯文字选中了仅文本配置后，追问补图会失败并提示重新发起，而不是切换执行端。
- 配置能力必须可准确描述：用户配置可显式声明是否支持图像；服务端默认配置由管理员配置 `agentVision`；fixture 验收配置可声明 `image:false`。
- 点 ✨ 时先校验：无可用配置不弹 Sheet，列表区直接 EmptyState + "去配置"（RN → `AgentProfileScreen`，Web → `AgentSetup`）。
- `AGENT_RUNTIME_DISABLED` 只关闭服务端执行路径：Web 入口不渲染；RN 配对服务端路径不渲染，练习模式/本机配置仍可用。
- 服务端运行在 `start` 响应和运行结果中返回脱敏配置摘要（ID、label、provider、model、version），供摘要卡展示；不返回密钥或尾号以外的凭据信息。
- 预设提供商含 `opencode`（OpenAI 兼容，固定端点 `https://opencode.ai/inference/go/v1`），服务端不开放自定义端点；验收 smoke 模型为 `deepseek-v4.1-flash-1017` 版本；2026-11-21 服务端列表中的调用 ID 是 `deepseek-v4.1-flash`（显示名 DeepSeek V4.1 Flash 1017，以列表为准）。真实密钥只存设备安全存储、服务端密文或 git 忽略的 `.env`，不进提交、文档与日志。

### R6 边界与异常状态

| 状态 | 行为 |
|---|---|
| 失败 | 摘要卡显示稳定错误码映射文案 + 重试（同输入新请求）+ 修改输入（回 Sheet） |
| 取消 | 用户取消或离开页面；候选停在上轮或回到空态 |
| 中断 | 本机进程退出或服务端重启后，客户端保留最近一次 AI run 引用；重进动作库时提示"上次检索未完成"，可重新发起；运行记录按 agent-runtime R6 留痕 |
| 图片超限/格式错误 | 共享任务在附件校验阶段拒绝，在面板或摘要卡展示拒绝原因；错误码 `agent_media_invalid` / `agent_media_too_large`，与 `turn_limit` 等同为本次新增到共享错误表的码 |
| 会话并发/轮次 | 并发 run 返回 `session_busy`；超过 5 轮追问返回 `turn_limit`，界面提示重新发起 |
| 关键词零结果 | 维持现状（含现有 Fuse 建议），不自动触发、不提供 AI 升级入口 |

## 非目标

- 首轮多张图片（单张；多角度经追问补图表达）。
- 追问自由问答（文字回答）、训练指导、计划生成——属智能训练指导范畴。
- AI 直接写入训练、计划或替换动作；加入/替换必须走现有选择器、详情页和训练写入入口。
- 识别历史与会话列表 UI（退出即删，无历史可浏览；服务端只保留短期清理窗口）。
- 图文叠加关键词检索；关键词零结果 AI 升级通道。
- 动作库和训练动作选择器以外的入口（如进度照片、历史编辑里的非动作选择场景）。
- 深链、Capacitor/iOS/watch 端兼容。
- 跨会话记忆；本任务不读取长期记忆，也不允许模型提议保存记忆。

## 技术设计输入

已由 [DESIGN](DESIGN.md) 细化：

- 任务输入 `{ hintText?, images?, fixtureCase? }`，`sessionId` 使用既有 `RunRequest.sessionId`；`images` 为内联 data URL，≤2 张：当前新图在前、上文图在后；每轮文字或图片至少一项。
- 模型输出双通道：`candidates[]`（动作名、可选英文名/器械/部位提示、依据、等级）+ `fallback`（理解描述、建议身体部位/器械筛选）**总是返回**。
- 模型不直接输出动作库 ID：候选名与提示经共享匹配管道解析；中文回退、歧义阈值和自建动作/别名规则在设计中固定。
- 图片保留在客户端（RN SQLite / Web 识别态内存），发起与追问时通过共享任务的附件钩子内联交给执行方；服务端不落盘，会话只存元数据。
- 执行位置首轮固定；追问不换端；长期记忆不读取；服务端按会话限制轮次并清理过期 AI 会话/运行记录。
- 静默默认配置解析顺序、会话图片预算、追问轮次预算已在技术设计中定稿。
