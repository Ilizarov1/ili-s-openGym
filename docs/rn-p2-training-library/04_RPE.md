# 04 RPE

## 需求

用户可在训练正式组记录主观用力程度，在训练历史更正或清除评分。力量组按工作区的评分模式显示入口，有氧采用 RPE 语义。评分是可选信息。

1. **录入**。设置「训练评分 → RPE」后，为重量次数正式组输入 8.5，可直接选择快捷评分或输入小数。按上游习惯，快捷步进从 6 开始，精确输入允许低于 6。
2. **保存与纠错**。记组、强制停止重开、完成训练后仍显示 RPE 8.5。能在统计历史更正或清除，重量、次数、完成标记和训练量保持一致。
3. **旧数据与有氧**。旧记录没有评分时显示为空，有氧可记录 RPE，热身和计时组沿用当前记录入口。关闭评分设置后，已保存评分仍能从历史读到。

## 实现设计

- 设置沿用 `profile.effort` 与上游 `effortOf` 的模块/旧偏好规则。配对时用现有变更队列写回。草稿保存评分尺度与数值，历史写标准 `set.rpe`；一组只保存一个尺度，清除时删字段。参考 [effort.js](../../frontend/src/lib/effort.js) 和 [评分上下限与步进](../../frontend/src/lib/history.js)。
- 活动训练和历史纠错共用评分选择逻辑。UI 用现有 `ActionSheet` 或 `Sheet` 和 `Stepper`，明确保存、清除和取消。RN 精确输入使用有限值 0–10，快捷步长 0.5。导入的评分按原值读回。
- 在 `SettingsScreen` 加评分设置，在 `WorkoutScreen`、`HistoryEditorScreen` 接写入，在 `StatsScreen` 的组摘要和单动作历史接读回。高级组可给整组评分，评分更新独立于记组与计时。

## 执行步骤

1. 先实现评分读写与草稿序列化，再接设置、训练组菜单和历史纠错。用普通组、递减组、有氧和无评分旧记录做 fixture。
2. 在可见模拟器验证 8.5、低于 6 的精确值、空值、取消和清除。断网保存后重开，恢复网络并核对 API 保存 `rpe`、清除后字段消失、原组训练量未变化。
3. 执行 [共用验收](README.md#共用验收)，记录评分设置、训练和历史的截图，以及同步读回。
