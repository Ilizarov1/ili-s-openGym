## 开发顺序

1. 适配 `android-regression.ps1` 的新导航和菜单位点，先重跑超级组场景，建立本批改动前的对照结果。
2. 训练侧先做递减组，再做休息暂停组，共用高级组输入、落盘和历史回读。随后接入 RPE，再补 RIR 的尺度和兼容规则。
3. 动作库可与训练侧并行推进。先接收藏和筛选，再把详情与演示接入独立浏览和动作选择场景。`App.tsx`、`training.ts`、`profileChanges.ts` 有共享字段和回调，集成时按当前接口合并。

## 共用验收

- **数据**。训练草稿继续用 SQLite，已配对工作区沿用待同步队列和 `/api/data` 的 `baseRev`、`baseWid` 及 `409` 重试。用独立 API 核对 RN 写入、Web 读回、离线重开、重试幂等和并行修改保留。
- **历史纠错**。高级组和评分只提交用户修改的组及字段。扩展现有历史保存路径时，重放基于最新记录，按训练键、动作位置和 ID、组位置与可用的 `at` 核对目标。组已删除或无法确认时保留服务器记录并提示重开历史。旧组无新字段时正常展示，已有 `sides`、`failure`、热身等字段按原格式读回。
- **界面**。复用 [设计系统](../RN_UI_DESIGN_SYSTEM.md)、[五入口页面结构](../RN_UI_SCREEN_MIGRATION.md) 和 [视觉验收流程](../RN_UI_VISUAL_TESTING.md)。在 `mobile-rn/` 运行 `npm.cmd run typecheck`、`npm.cmd run design:check`，打开专用 Android 模拟器，用 Debug fixture 与 `ui-capture.ps1 -Fixture` 验证布局。实际计时、持久化和同步用正常启动的 APK、ADB 功能脚本和 API 回读验证。
- **交付**。每项实现后更新 [迁移清单](../RN_MIGRATION_STATUS.md) 的状态和证据。批次完成后联跑 P0、P1、超级组及本批新增场景，记录 Release 版本、签名、SHA-256 和待验收项。
