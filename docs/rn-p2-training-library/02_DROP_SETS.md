# 02 递减组

## 需求

力量训练用户可在计划里设置每组降重段数和降重比例，或在训练时给某个正式组追加降重段。每段重量和次数可改，整组记组后能在历史展开和纠错。

1. **生成**。计划包含两次降重、比例 20%。按训练时的正式组重量及可用重量档生成可编辑段。热身维持原有结构。
2. **记录**。自由训练可加、改、删降重段，删除最后一段会恢复普通组。各降重段内不触发普通组间休息；整组完成后才推进下一组或超级组成员。
3. **读回与计算**。记录 `100×5 → 80×5 → 64×5`，同一计重口径下训练量为 1220，历史标记为一组。断网重开、纠错、同步和单位转换后，主组及各段数据均可读回。

## 实现设计

- 计划使用 `intensifier: { type: 'dropset', count, pct }`，记录使用 `type: 'dropset'` 和 `drops: [{ w, r }]`。主组次数只代表主组，降重段另计。规则来自 [上游组结构](../dev/SET_TYPES.md) 和 [workout-model.js](../../frontend/src/lib/workout-model.js)。
- 在 [training.ts](../../mobile-rn/src/training.ts) 适配 [上游 `applyIntensifierPlan`](../../frontend/src/lib/history.js)，在最终工作重量确定后生成。复用 `dropGrid`、`nextDropWeight`、`addDrop`、`setDropAt`、`removeDropAt`；验证段数、重量、降幅和次数，输入无效时显示对应字段提示。
- `PlanEditorScreen` 用 `Stepper` 配计划，`WorkoutScreen` 用组菜单追加、行下编辑，历史与单动作详情复用同一个摘要读法。历史可编辑 RN 合计行，保留 Web 已有的逐侧数据。训练结束和历史更正复用上游训练量计算。单位转换覆盖 `drops[].w`、有逐侧记录时的各侧负重及附加段，不换算次数或百分比。

## 执行步骤

1. 先接数据生成、增删和序列化，再接计划、训练、历史。测试计划缺省、手动转递减组、删除末段及替换同类型力量动作后保留计划配置。
2. 用 ADB 和上述 fixture 记录三段，重启再完成，核对历史显示、1220 训练量及千克/磅同步后各段重量。和同一超级组的其他成员联跑，验证整组只推进一次。
3. 执行 [共用验收](README.md#共用验收)，在迁移清单记录 API 中的 `type/drops`、计算结果和候选 APK。

## 验收目标

| 编号 | 前置条件 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 力量计划正式组 100 kg×5、两次降重 20%，固定测试档位允许 80 和 64 kg，另有热身 | 保存计划、重开并开始 | 每个正式组有 80 和 64 kg 两个可编辑段，主组仍为 100 kg×5；热身为普通热身 |
| 2 | 自由训练中有未记的普通组 | 转成递减组，调整段重量和次数，再移除所有降重段 | 编辑只更新对应段；段数为零时恢复普通组，主组的重量和次数可读回 |
| 3 | 有一个降重段次数为空或为 0，另用负重量测试 | 尝试记组，再纠正输入 | 无效时无法记组并有反馈；纠正后整个递减组只增加一个完成组 |
| 4 | 负重按记录值计一次，录入 `100×5 → 80×5 → 64×5`，排除热身 | 断网重开、完成、查看历史并同步 | 仍是一个正式组，训练量 1220，API `type/drops` 与历史段值一致 |
| 5 | 来源以 lb 记 100/80/64，各段 5 次，目标工作区为 kg | 同步回读目标资料，编辑其中一个降重段 | 重量约为 45.36/36.29/29.03 kg，次数仍为 5；纠错后训练量按新段值更新 |
| 6 | 递减组在超级组第一成员 | 编辑和完成递减组 | 各子段编辑期间仍指向第一成员；整组记组后才推进一次 |
